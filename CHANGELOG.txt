# Changelog

## [0.2.10] - 2026-07-30

### Fixed

- **SearchTokensBackfill in ActiveRecord environments.** `load_active_record_models!`
  now requires file-based, episodic, and procedural `ActiveRecordStorage` before
  calling `load_models!`, so `bundle exec rake llmemory:backfill_search_tokens`
  works in Rails without first initializing storage via `Storages.build`.

### Notes

- `release:bump` no longer strips `###` section headers from release notes (only
  optional top-level `#` / `##` titles).
## [0.2.9] - 2026-07-30

### Added

- **Rails Railtie.** `Llmemory::Railtie` loads `llmemory` rake tasks when the gem
  is required in a Rails app, so `bundle exec rake llmemory:backfill_search_tokens`
  works without a manual task require. The task depends on `:environment` when
  that task exists.

### Notes

- Migration docs updated to describe automatic task registration via the Railtie.

## [0.2.7] - 2026-07-23

### Added

- **Unified cognitive retrieval.** `Retrieval::MultiSource` feeds the retrieval
  engine from semantic (file/graph), episodic and procedural memory in one pass;
  `Memory#retrieve` now surfaces episodes and skills by default alongside facts.
- **Short-term CAS API.** `Stores#update(user_id, session_id) { |state| … }` on
  all short-term backends (MemoryStore mutex, Redis WATCH/MULTI/EXEC, Postgres
  FOR UPDATE, ActiveRecord lock). RMW writers migrated: `add_message`,
  `WorkingMemory`, `ForgetLog`, `UsageLedger`, `FeedbackStore`.
- **Batch fact classification.** `FactExtractor#classify_items` classifies many
  facts in one structured-output LLM call (fallback to per-item on failure).
- **Dashboard HTTP auth.** `config.dashboard_auth` and
  `config.dashboard_require_auth` gate the Rails dashboard outside development.
- **LLM HTTP client.** Shared `Llmemory::LLM::HttpClient` (Faraday) with
  timeouts and retries for OpenAI/Anthropic providers.
- **KeyCodec.** Short-term store keys encode `:` in user/session ids to avoid
  collisions.
- **ActiveRecord race retry.** `ActiveRecordHelpers#with_unique_retry` on
  short-term checkpoints, vector embeddings, and episodic/procedural/file AR
  storages.

### Changed

- **`FileBased#retrieve`** now uses `search_candidates` + `ContextAssembler`
  (same path as `Retrieval::Engine`) instead of the legacy 3-LLM pipeline in
  `file_based/retrieval.rb`.
- **`EntityRelationExtractor`** truncates long conversations preserving ~70%
  head + ~30% tail (marker `[...]`) so recent facts are not dropped.
- **Graph node matching** in `extract_node_ids_from_text` uses token overlap
  instead of `String#include?` (avoids false positives on short names).
- **Redis short-term store** uses `SCAN` instead of `KEYS` for
  `list_users`/`list_sessions`; Postgres `ensure_table!` is memoized per
  instance; PG/Redis connections guarded by a per-store mutex.
- **MCP HTTP server** binds to `127.0.0.1` by default; **`MCP_TOKEN` is
  required** when listening on a non-loopback address.
- **Consolidator** merge keeps `max(importance)` and the most recent
  `provenance` when deduplicating items.
- **`Provenance` confidence** maps `"high"`/`"medium"`/`"low"` to 0.9/0.6/0.3
  (numeric values clamped to [0, 1]).
- **TemporalRanker**, graph keyword scoring, vector-store deletes, and MCP tool
  store wiring refinements from the security/hardening pass.

### Fixed

- **`clear_session!`** also clears working memory slots.
- **Pruner** produces valid UTF-8 after byte-based soft-trim (`scrub`).
- **`SessionLifecycle`** skips sessions with corrupt `last_activity_at` instead
  of aborting cleanup.
- **Encryption** fail-fast on misconfiguration; clearer `DecryptionError`;
  `ForgetLog`/`WorkingMemory` use the instance short-term store (not global).
- **MemoryStore** returns deep copies; MCP dashboard XSS in short-term view;
  shared `:memory` stores for MCP when `shared_memory_stores` is enabled.

### Removed

- Unused **`vcr`** development dependency from the gemspec.

### Notes

- Distributed locks across separate processes (multi-worker beyond Redis WATCH /
  PG row locks) remain out of scope; MemoryStore mutex is process-local.
- KDF upgrade to PBKDF2 / `enc:v2` is still deferred (would break existing
  `enc:v1` ciphertext).

## [0.2.2] - 2026-06-08

### Added — closing the cognitive loop (SF18 + SF19)

- **Skill mining (SF18).** New `Llmemory::SkillMining::Miner` distills reusable
  skills from successful episode trajectories (Voyager's contribution: procedural
  memory grows from lived experience instead of being a hand-written library).
  Human-in-the-loop by default — `mine(window:, outcomes:, auto_register:)`
  returns skill proposals and writes nothing; `auto_register: true` registers
  them in procedural memory with provenance `{ method: "skill_mining", sources:
  [{ type: "episode", id: ... }] }` back to the source episodes. An optional
  `outcomes:` allowlist deterministically pre-filters episodes by outcome label.
  Exposed on the unified API as `Memory#mine_skills!`. Emits a new
  `mine_skills.llmemory` instrumentation event.
- **Skill provenance.** `Skill` gains an optional `provenance` field (document
  storages need no schema change); `register_skill`/`write` accept `provenance:`.
- **Cognitive maintenance pass (SF19).** New
  `Llmemory::Maintenance::CognitivePass.run!(user_id, ...)` orchestrates the
  learning loop in one scheduled step: consolidate → reflect → mine skills →
  TTL expiry. Each step is isolated — a failure is captured in the report
  (`:errors`) and never aborts the others. Returns an aggregated report
  `{ consolidated:, insights:, mined:, expired:, errors: }`. Components are
  injectable (like `TTLExpiry`) and built per-config when omitted. Exposed on the
  unified API as `Memory#maintain!`, which wires in the live session so
  `consolidate!` runs too. New `config.skill_mining_enabled` (default `false`)
  gates whether the pass auto-registers mined skills.

### Added — maintenance surface (SF20)

- **MCP tools.** `MemoryMaintain` (run the pass, return a summary report) and
  `MemoryMineSkills` (mine proposals; human-in-the-loop, or `auto_register`).
- **CLI commands.** `maintain USER_ID` (`--[no-]reflect` / `--mine-skills` /
  `--[no-]expire` / `--window` / `--store`) and `mine-skills USER_ID`
  (`--window` / `--outcomes` / `--register` / `--store`).
- **Rails Dashboard.** A maintenance page per user: trigger a pass, and mine
  skill proposals to review and register one-by-one before they hit procedural
  memory. Linked from the user show page.


## [0.2.1] - 2026-05-27

### Added — episodic/procedural parity & search quality (SF1–SF3)

- Episodic and procedural memory now support `:postgres` and `:active_record`
  backends (each record stored as a JSONB `data` document, like checkpoints).
  Migration adds `llmemory_episodes` and `llmemory_skills`.
- Opt-in semantic (embedding) retrieval for episodic and procedural memory
  (`config.episodic_vector_enabled` / `config.procedural_vector_enabled`, default
  off). When enabled, `search_candidates` is hybrid (vector + keyword).
  `VectorStore::ActiveRecordStore` now namespaces embeddings by `source_type`.
- Keyword search is tokenized (`Llmemory::Tokenizer`): multi-word queries match
  across non-contiguous terms instead of requiring a contiguous substring.

### Added — graph parity, orchestrator ergonomics & operability

- **Graph forgetting (SF4).** `GraphBased::Memory#forget(ids:, reason:)` archives
  the edges identified by the candidate ids returned from `read`/`search_candidates`,
  with audit via `ForgetLog`. Edge ids are normalized (no double "edge_" prefix)
  so candidate id == edge id.
- **Graph as a reflection target (SF7).** `GraphBased::Memory#remember_fact(content:,
  provenance:, ...)` extracts entities/relations from the insight content and adds
  them with the supplied provenance. `Reflection::Reflector` now targets graph-based
  semantic memory transparently.
- **Orchestrator ergonomics (SF9).** `Memory#episodic`, `Memory#procedural`,
  `Memory#reflect!(window:, category:)` and `Memory#reason(template:, into:, parse:)`
  exposed on the unified API (lazy, injectable).
- **MCP cognitive tools (SF10).** Six new tools: `MemoryEpisodeRecord`,
  `MemoryEpisodes`, `MemorySkillRegister`, `MemorySkillReport`, `MemorySkills`,
  `MemoryForget`.
- **CLI cognitive inspection (SF10).** Four new commands: `episodes USER_ID`,
  `skills USER_ID`, `working USER_ID SESSION_ID`, `forget-log USER_ID`.

### Changed — pseudo-session safety (SF6 + SF12)

- `SessionLifecycle` now identifies pseudo-sessions used by `ForgetLog`,
  `FeedbackStore` and `WorkingMemory` and excludes them from
  `cleanup_idle_sessions!`, `cleanup_stale_sessions!` and `enforce_max_entries!`.
  Audit, retrieval feedback and working-memory slots are never evicted as if
  they were user sessions.

### Added — medium-tier operability (SF5, SF10 sub, SF13, SF14)

- **Pagination (SF14).** `MemoryModule#list(user_id:, limit:, offset:)` now
  takes a uniform `offset:` across all four long-term memories and all storage
  backends (memory, file, postgres, active_record). SQL backends use
  `LIMIT/OFFSET`; in-memory storages slice the sorted array.
- **Observability hooks (SF13).** New `Llmemory::Instrumentation.instrument`
  publishes `ActiveSupport::Notifications` events when AS is loaded (no-op
  fallback otherwise): `llm_invoke.llmemory`, `llm_embed.llmemory`,
  `memory_write.llmemory`, `memory_forget.llmemory`, `retrieve.llmemory`,
  `iterative_retrieve.llmemory`, `reflect.llmemory`. Wired into LLM providers,
  the OpenAI embedder, the retrieval engine, the reflector and every memory's
  write/forget path.
- **Forget modes + TTL (SF5).** `forget(ids:, reason:, mode: :soft | :hard)`
  on all memories. `:soft` (default) archives the entries (excluded from
  list/search/retrieval, still accessible by id); `:hard` physically deletes.
  Episodic and procedural gain a true `archived_at`-flagged soft archive
  (memory, file, postgres, active_record); file-based and graph-based document
  their existing semantics. New `Llmemory::Maintenance::TTLExpiry.run!(user_id)`
  job soft-archives entries older than `ttl_episodic_days` / `ttl_procedural_days`.
- **Rails Dashboard cognitive surface (SF10 sub).** Engine ships
  episodic / procedural / working-memory / reflection / forget-log pages with
  forget actions (soft + hard) and a reflection trigger. Links surfaced on the
  user show page.

### Notes

- Episodic/procedural SQL & vector backends are not exercised in CI (no database
  or embedding API), consistent with the other SQL backends.
- Deferred follow-ups (with explicit rationale): **SF8** (graph provenance
  linked to a persisted source — no demand for literal source reconstruction
  beyond the SHA-256 fingerprint); **SF11** (refactor `consolidate!` onto
  `Actions::Reason` — risk > immediate gain); plus the speculative cognitive
  extensions (SF18–SF19) and the lower-tier operability items (SF15–SF17).


## [0.2.0] - 2026-05-27

### Added — Cognitive Memory (CoALA)

Implements the memory and internal-action model from CoALA (Cognitive
Architectures for Language Agents, Sumers et al. 2024).

- Episodic long-term memory (`LongTerm::Episodic::Memory`): records experience
  trajectories (observation → action → result); `:memory` and `:file` backends.
- Procedural long-term memory (`LongTerm::Procedural::Memory`): a Voyager-style
  skill library with auto-versioning and success/failure tracking; skill success
  rate is surfaced as importance during retrieval.
- Structured working memory (`Llmemory::WorkingMemory`): symbolic slots that
  persist across LLM calls, backed by the short-term stores under a namespaced
  session key. Exposed on the unified API as `Memory#working_memory`.
- Reflection (`Reflection::Reflector`): distills recent episodes into semantic
  insights (Reflexion / Generative Agents pattern), traceable to source episodes.
- Reasoning action (`Actions::Reason`): render a prompt from working memory,
  call the LLM, write the result back — composable, long-term-free.
- Uniform memory interface (`Llmemory::MemoryModule`): `read`/`write`/`list`/
  `stats`/`forget` across file/graph/episodic/procedural memories.
- Provenance (`Llmemory::Provenance`): lineage on items, graph nodes/edges and
  reflection insights (sources, method, confidence). Graph records a SHA-256
  fingerprint of the source text.
- Adaptive retrieval feedback (`Retrieval::Engine#report_feedback`,
  `Retrieval::FeedbackStore`): useful/harmful signals reweight future ranking.
- Iterative (multi-hop) retrieval (`Retrieval::Engine#iterative_retrieve`):
  reason about missing information between retrieval hops.
- Forgetting with audit (`Memory#forget` / `MemoryModule#forget`,
  `Llmemory::ForgetLog`): remove entries by id with a recorded audit trail.
- Importance is now a tunable ranking signal (`config.importance_weight`);
  feedback strength is tunable via `config.retrieval_feedback_weight`.

### Notes

- Episodic/procedural SQL & ActiveRecord backends, vector search for those two,
  and graph forgetting are tracked as follow-ups.
